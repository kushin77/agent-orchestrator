## What this is (30 seconds)

A repository should not have to hand-write its agent fleet. It declares a few
parameters -- its own id, the SME domains it cares about, which model sits on
each tier, and its FinOps ceilings -- and the shared template renders the rest:
the five roles, one SME per domain, lens routing, the budget ceilings and the
run-state block.

Three properties make that a product rather than a snippet:

1. **Parameterized.** Nothing in a rendered instance is hand-edited. The
   committed instance is generated by `render.py` from a params file, and the
   gate fails if the two ever disagree (drift).
2. **Isolated.** Every identity, state path and worktree prefix is derived from
   the `repo` parameter, so two repositories' fleets share no identity and no
   state. That is checked, not asserted.
3. **Honest about run state.** The composition is *declared*; what is actually
   running is *observed*. A declared member with no observation is
   `unverified`, and `unverified` is never reported as present.

The lane is **declared data + schema + gate**: the template, the params, the
rendered instances and the recorded run-state are YAML documents validated
against [`schema.yaml`](../control-plane/fleet-template/schema.yaml), and
[`check-fleet-template.sh`](../scripts/check-fleet-template.sh) turns any
disagreement into a failing signal.

## How a repo instantiates its own fleet

1. **Copy a params file as a starting point**, not a template file:
   [`pilots/agent-orchestrator.params.yaml`](../control-plane/fleet-template/pilots/agent-orchestrator.params.yaml)
   is the worked example. It declares only parameters (`repo`, `domains`,
   `model_tiers`, `budget`, optionally `display_name`).
2. **Record what is actually running** in an observation file (see
   [`pilots/shared-frontend.observations.yaml`](../control-plane/fleet-template/pilots/shared-frontend.observations.yaml)).
   Omit it entirely and every required member is honestly `unverified`.
3. **Render the instance into the tree** (this is the committed artifact):

   ```bash
   python3 control-plane/fleet-template/render.py \
     render --params control-plane/fleet-template/pilots/<repo>.params.yaml \
     --out    control-plane/fleet-template/pilots/<repo>.fleet.yaml
   ```

4. **Run the gate** -- `bash scripts/check-fleet-template.sh` -- and commit both
   the params and the rendered instance. Editing `template.yaml` requires
   re-rendering every pilot in the same change; the gate will say so if you
   forget.

The pilot file name is load-bearing: `<stem>.params.yaml` renders to
`<stem>.fleet.yaml` and `<stem>` must equal the `repo` parameter. A mismatch is
a finding (`PILOT_NAME_MISMATCH`), because the instance path is derived from the
name.

## The parameter surface

| Parameter | Meaning | Effect on the rendered fleet |
|---|---|---|
| `repo` | repository id (required) | namespaces `fleet_id`, `state_prefix`, `worktree_prefix`, `lane_namespace` and every member id |
| `display_name` | human label (optional, has a template default) | `metadata.display_name` |
| `domains` | SME domains covered (required) | one SME member, one lens route, one `domain_to_role` edge and one `per_domain` ceiling each |
| `model_tiers` | `tier -> model` (required) | binds `model` on every role and SME through its tier |
| `budget` | FinOps ceilings (required) | `definition.finops` and the ceilings every invariant is measured against |

Two substitution forms exist, both in `render.py` and both schema-declared:

* `${path.to.param}` -- a placeholder. When the whole scalar *is* the
  placeholder, the value keeps its type (a list, a dict, an integer), which is
  how the budget object and the domain list pass through unchanged. When it is
  embedded in a longer string (`fleet-${repo}`) it interpolates as text, and a
  container in that position is a hard failure rather than a `repr()` surprise.
* `$for_each` / `$as` / `$template` (plus `$key` / `$value`) -- a list
  expansion over a parameter, or a mapping when `$key`/`$value` are present.
  This is what turns the `domains` parameter into the SME squad, the lens
  routing and the domain map in one place instead of three.

`$for_each` names a parameter *path* (`domains`, `budget.per_role`); `$key` and
`$value` are interpolations. The distinction is in the schema so a template that
confuses them fails validation rather than rendering something surprising.

## Definition vs run-state

This is the harvest the lane exists to carry forward: what a fleet *is* and what
it is *doing* are different facts, and a system that conflates them reports a
composed-but-not-running fleet as healthy.

| Run state | Meaning | Counted as present? |
|---|---|---|
| `required` | declared required **and** observed running | yes |
| `parked` | declared parked (an intentional non-runner, e.g. the advisor seat) | no |
| `unverified` | declared required, **no observation available** | **never** |

`definition.smes[].state` and `definition.roles[].state` are the *declaration*
(`required` or `parked` -- `unverified` is not declarable, because it is a fact
about observation, not a composition choice). `run_state.tri_state` is the
*observation*, and `run_state.present` is the observed subset of the required
members. So the honest statement "I do not know" has its own slot and is never
rounded up to "present".

Four invariants hold the split in place, all in `check_invariants`:

* `present == tri_state.required`, and `present` never intersects
  `tri_state.unverified` (`UNVERIFIED_REPORTED_PRESENT`).
* a member declared `parked` that is *observed* running is a finding
  (`PARKED_MEMBER_OBSERVED`) -- the declaration and reality disagree and the
  declaration does not get to win silently.
* an observation naming a member that is not in this fleet is a finding
  (`OBSERVATION_FOREIGN_MEMBER`) -- that is a cross-fleet leak, not data.
* the tri-state partitions the declared members and the counts match the lists.

## Isolation rule

Two repositories' fleets must share **no identity and no state**. The mechanism
is single-sourced: everything namespaced is derived from `repo`.

| Field | Derivation | Sharing it means |
|---|---|---|
| `isolation.fleet_id` | `fleet-<repo>` | two fleets are one fleet |
| `isolation.state_prefix` | `.fleet/<repo>` | two fleets write into one state directory |
| `isolation.worktree_prefix` | `ao-<repo>-` | two fleets cut indistinguishable lane worktrees |
| `isolation.lane_namespace` | `<repo>` | two fleets claim the same lanes |
| every member `id` | `<repo>:<role>`, `<repo>:sme:<domain>` | one work item is claimed twice |

`check_isolation` reports a shared or a **nested** `state_prefix` (one fleet's
state living inside another's), a shared member id, and a shared namespace --
and `check_invariants` reports a member id that is not namespaced by its own
repo. The two committed pilots are rendered from the same template with
different params, and their namespaces and member sets are asserted disjoint in
`tests/test_isolation.py`.

## Drift rule

A template that only exists in the author's head is a template nobody follows.
Drift is detected at three levels, each with its own finding code:

| Code | What it means |
|---|---|
| `RENDER_DRIFT` | a value in the committed instance differs from a fresh render of its params |
| `PARAMS_SHA_DRIFT` | the params file changed but the instance was not re-rendered |
| `TEMPLATE_SHA_DRIFT` | the template changed but the instance was not re-rendered |
| `PARAMS_DIGEST_DRIFT` | the recorded parameter values no longer match the params file |
| `PILOT_INSTANCE_MISSING` | a pilot has params but no committed instance |

Drift is `NOT-OK`, not `CANNOT-ASSESS`: the documents are well-formed, they
simply disagree. `tests/test_drift.py` and `tests/test_negative_controls.py`
each provoke a drift, require the finding, then disable `check_drift` and
require the same corruption to become invisible -- which is what proves the
detection comes from the check and not from something incidental.

## Exit-code contract

`render.py` and the shell gate both speak the repo's honesty tri-state
([`../guardrails/honesty/tristate.py`](../guardrails/honesty/tristate.py)):

| Code | Status | When |
|---|---|---|
| 0 | OK | every pilot renders and matches its params; no invariant or isolation finding |
| 1 | NOT-OK | drift, an invariant violation, a missing/mislabelled pilot, a shared namespace |
| 2 | CANNOT-ASSESS | an input is missing or unparseable, or a document violates `schema.yaml` |

A schema violation is **CANNOT-ASSESS (2), never 0**: a document that does not
satisfy the declared contract has not been assessed, so it cannot be reported as
sound. Also note the two aggregation facts the gate relies on: `CANNOT-ASSESS`
never reads as a pass, and a real defect (`NOT-OK`) outranks an unassessable
input. `tests/test_cli_exit_codes.py` and
`tests/test_negative_controls.py` drive the shell gate through all three codes
on scratch copies of the lane.

## Gate

```bash
bash scripts/check-fleet-template.sh          # 0 / 1 / 2 as above
python3 control-plane/fleet-template/render.py check      # the same, machine-readable with --json
python3 control-plane/fleet-template/render.py report --params <params>   # run-state tri-state
python3 control-plane/fleet-template/render.py validate-instance <file>
python3 -m pytest control-plane/fleet-template/tests -q
```

The shell gate is intentionally **not** wired into `scripts/verify.sh`: that file
is a shared resource owned by the orchestrator, which wires the signal in after
this lane merges. Until then, `make verify` is unaffected by this lane and the
gate is run directly as above.

## Blast radius

* **Additive.** New files only: `control-plane/fleet-template/**`,
  `scripts/check-fleet-template.sh` and this document. No existing file, target
  or gate is modified; `make verify`'s check list is unchanged.
* **No network, no containers, no credentials.** The renderer is Python stdlib +
  PyYAML; it reads the files it is pointed at.
* **Nothing here starts a process.** A rendered instance is a declaration. This
  lane does not spawn agents, register them, or write into `.fleet/`; the state
  paths it names are namespaces for a future runner to honour.
* **Fail-closed.** A lane whose schema is missing, whose template is missing, or
  whose pilot set is empty is CANNOT-ASSESS -- an empty fleet set never renders
  as a clean one.

## What this lane does not do

* It does not enumerate or reconcile *live* sessions -- that is
  `governance/reconcile/`. This lane only defines the shapes and the gate.
* It does not implement the model gateways or the FinOps ledger -- the ceilings
  are declared here and enforced by `gateway/finops/**`.
* It does not mutate GitHub labels or create worktrees; the harvested
  implementations did both, and that is exactly the part that was left behind
  (see PROVENANCE).
