## What this is (30 seconds)

The C-suite seats are declared twice on `master` — as workbook-1 **PersonaCards**
(`registry/personas/cards/{ceo,cto,coo,cfo,cmo}.yaml`) and as workbook-8 **prompt
modules** (`registry/prompts/modules/{role}-primary.v1.yaml`) — but neither is an
instruction-layer entry.  A harness reading `AGENTS.md`, `CLAUDE.md`,
`.cursorrules` or `copilot-instructions.md` therefore had no C-suite rule set to
follow.

This subtree closes that gap using the mechanism the parent lane already
productizes: **ONE canonical instruction source per seat, DERIVED from the
workbook artifacts**, rendered deterministically into all four per-tool mirrors,
with a conformance suite proving the same rules and precedence reach every
harness.

The canonical sources are **derived, never authored**.  A hand-written second
copy of the tier ladder, the budget caps, the reporting lines or the constraint
sets is exactly the drift the instruction layer exists to prevent; here a change
to a card or a prompt module flows through `derive.py` into every mirror.

## Derivation (AC1)

`csuite/derive.py` reads the five PersonaCards and the five prompt modules
**read-only** (GR-3: the registry and prompt lanes keep ownership of those
files) and emits five governed layers per seat, ordered most-governing first:

| # | Layer | Source |
|---|---|---|
| 1 | `platform` | the org-chart edge (`ceo -> board`, others `-> ceo`) + the session-identity binding |
| 2 | `csuite-role` | the workbook-1 card (tier, monthly cap, heartbeat) + the workbook-8 module it renders from |
| 3 | `workbook-mechanical` | the workbook-6 mechanical rule: policy id, action, gate attribute |
| 4 | `repo-governance` | the card's `constraintSet`, verbatim and in declaration order |
| 5 | `seat-expectations` | the card's role `guardrails`, verbatim and in declaration order |

Rule ids are namespaced by source (`platform--`, `seat--`, `workbook--`,
`constraint--`, `guardrail--`) so they are unique set-wide without inventing new
vocabulary.  The canonical contract admits only `[a-z0-9-]` in an id, hence the
`--` separator.  Every rule in every layer is `managed: true`: the whole C-suite
entry is platform-issued, so a tenant override may add local rules but can never
redefine one of these.

```bash
# print a seat's derived canonical source (no writes)
python3 -m csuite.derive --role ceo
# regenerate canonical sources + mirrors + consumer states for all five seats
python3 -m csuite.derive --write
```

## Per-tool mirrors: generated, never hand-forked (AC2)

Each canonical source is rendered by the shared `aoi` renderer — the same
`MIRROR_TARGETS` and the same ledger format as any other instruction set.  No
C-suite-specific render path exists: `csuite` is a *producer* of canonical
sources; `aoi` remains the single renderer.

| Mirror | Consumed by |
|---|---|
| `AGENTS.md` | generic / DeepSeek harness (model-agnostic) |
| `CLAUDE.md` | Claude Code |
| `.cursorrules` | Cursor |
| `copilot-instructions.md` | GitHub Copilot |

```bash
python3 -m aoi render --canonical csuite/canonical/ceo.yaml --out csuite/rendered/ceo --check
# -> render: byte-stable — 4 mirrors match regeneration
```

A hand edit of any mirror breaks byte-stability and is a hard failure; the
committed `csuite/rendered/<role>/` set IS the byte-stable proof artifact.

## The mirror set

Five seats × four harnesses = 20 mirrors, plus five distribution manifests and
five pinned consumer states:

```text
csuite/
├── derive.py                       # the derivation (read-only consumer of registry/)
├── canonical/<role>.yaml           # 5 canonical instruction sources (DERIVED)
├── rendered/<role>/
│   ├── AGENTS.md                   # \  generated by `aoi` from the
│   ├── CLAUDE.md                   # |  canonical source — never hand-forked
│   ├── .cursorrules                # |
│   ├── copilot-instructions.md     # /
│   └── distribution-manifest.json  # sha256 of every mirror
├── consumer/<role>.json            # pinned, compliant consumer state (drift-checked)
└── tests/
    └── test_csuite_mirrors.py      # conformance + derivation + determinism + mutation proof
```

## The conformance suite proves the same rules reach every harness (AC3)

```bash
python3 -m aoi conformance --dir csuite/rendered/ceo --canonical csuite/canonical/ceo.yaml
# -> conformance: PASS — identical rules + precedence in every mirror
```

`csuite/tests/test_csuite_mirrors.py` runs that check for **all five seats** and
adds the proof obligations the acceptance criteria name:

* **derives from the workbook artifacts** — the committed canonical source must
  equal `derive_canonical(role)`, and the card's tier / cap / cadence / reporting
  line / `constraintSet` / `guardrails` and the module's `policyId` / `action` /
  `gate attribute` must all be present in it (a hand-written entry fails);
* **generated deterministically** — regeneration must be byte-identical to the
  committed mirrors, the manifests must match regeneration, and the derivation
  must be a pure function of the artifacts (same artifacts, same digests);
* **conformance across harnesses** — the four ledgers of a seat must agree on
  the ordered rule set and precedence, every mirror must carry every rule
  statement, and the five seats must have five distinct rule signatures (no
  copy-paste derivation);
* **negatives (the suite can fail)** — a missing mirror, a reordered rule, a
  hand-forked rule statement (with sha256 before/after), a mirror stripped of its
  ledger, and another seat's mirror set all FAIL conformance.

## Relationship to the parent lane

`control-plane/instructions/README.md` describes the model-agnostic instruction
layer itself: the canonical model, the renderer, the frozen tenant-override
contract, the distribution/drift mechanism and the conformance checker.  This
subtree is a **consumer** of all of it — it adds the five C-suite canonical
sources the layer was missing, deriving them from the workbook declarations
instead of authoring a sixth copy of that governance.
