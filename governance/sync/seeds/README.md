# Seeds — governance/sync offline demo ecosystem (issue #44)

A self-contained, fully offline ecosystem for the sync/drift engine. Content
pins are generated by the real `provenance.generate_manifest` generator, so
the manifests, canonical mirror and catalog always agree.

```text
seeds/
├── catalog.json          # dependency catalog (ao.sync/dependency-catalog-v1)
├── canonical/            # canonical source mirror (the "source repos")
│   ├── shared/*.txt      #   core-guardrails, pack-sync-engine, portal-shell,
│   │                     #   design-tokens
│   └── vendor/unrelated-asset.txt   # rogue fixture's only asset
└── consumers/            # one provenance manifest per consumer
    ├── acme.json         #   core-guardrails + pack-sync-engine + design-tokens
    ├── globex.json       #   core-guardrails + pack-sync-engine
    ├── nexus.json        #   core-guardrails + portal-shell
    ├── zeta.json         #   core-guardrails (direct consumer)
    └── rogue.json        #   unrelated-asset ONLY (blast-radius negative fixture)
```

## What each piece demonstrates

| Piece | Demonstrates |
|---|---|
| `canonical/` | The canonical source mirror a drift check compares against; deleting a file there makes that asset `cannot-assess` (never clean) |
| `consumers/acme|globex|nexus|zeta` | Real vendoring consumers of shared assets (drift CLEAN when in sync, DRIFT when tampered) |
| `consumers/rogue` | A consumer outside every shared asset's dependency graph — never reported by blast radius |
| `catalog.json` | Transitive dependencies: `portal-shell -> pack-sync-engine -> core-guardrails` |

## Reproduce the CLI demo

```bash
SYNC=governance/sync
# 1. provenance validate every consumer manifest (expect rc=0, 0 findings)
python3 $SYNC/cli.py provenance validate $SYNC/seeds/consumers/*.json

# 2. materialize a consumer local tree (in sync) and drift-check it CLEAN
mkdir -p /tmp/ao44-local/shared && cp $SYNC/seeds/canonical/shared/*.txt /tmp/ao44-local/shared/
python3 $SYNC/cli.py drift $SYNC/seeds/consumers/acme.json \
  --local-root /tmp/ao44-local --canonical-root $SYNC/seeds/canonical     # rc 0 clean

# 3. tamper one vendored asset -> DRIFT (rc 1)
echo "local tamper" >> /tmp/ao44-local/shared/core-guardrails.txt
python3 $SYNC/cli.py drift $SYNC/seeds/consumers/acme.json \
  --local-root /tmp/ao44-local --canonical-root $SYNC/seeds/canonical

# 4. blast radius: wide shared asset -> 4 consumers; leaf -> 1; transitive -> 3
python3 $SYNC/cli.py blast core-guardrails \
  --manifests $SYNC/seeds/consumers --catalog $SYNC/seeds/catalog.json
python3 $SYNC/cli.py blast design-tokens \
  --manifests $SYNC/seeds/consumers --catalog $SYNC/seeds/catalog.json

# 5. sync plan (dry-run default), then explicit apply against a v2 canonical
python3 $SYNC/cli.py sync plan $SYNC/seeds/consumers/acme.json --desired desired.json
```

Expected blast-radius counts: `core-guardrails` -> 3 assets / 4 consumers
(acme, globex, nexus, zeta — rogue excluded); `design-tokens` -> 1 asset /
1 consumer (acme); `pack-sync-engine` -> 2 assets / 3 consumers (acme, globex
via direct pin, nexus via `portal-shell`).
